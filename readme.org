** About
A permissively licensed modern implementation of Gauss-Jacobi quadrature which returns the weights and nodes over the standard interval ~[-1, 1]~.
** Usage
The most automated approach is to use the ~conda~ environment and ~fpm~ build:
#+begin_src bash
micromamba create -f environment.yml
micromamba activate gaussjacquad
# Coarray Fortran is required (-fcoarray=single is the portable 1-image mode)
fpm build --flag "-fcoarray=single"
#+end_src

An analytic result can be obtained from the ~scripts~ folder.
#+begin_src bash
python scripts/sympy_gauss_jac.py --npts <npoints> --alpha <alpha> --beta <beta> --n_dig <precision>
fpm test --flag "-fcoarray=single"
#+end_src

Running the implemented recursion based Gauss-Jacobi can be done via:
#+begin_src bash
fpm run --flag "-fcoarray=single" gjp_quad_rec -- <npoints> <alpha> <beta>
fpm run --flag "-fcoarray=single" gjp_quad -- <npoints> <alpha> <beta> <method>
#+end_src

Supported methods (see [[file:docs/METHODS.org][docs/METHODS.org]]):
~auto~ (default policy), ~rec~/~rec_caf~, ~gw~, ~algo665~/~algo665_dc~,
~sturm~/~sturm_caf~, ~glr~/~glr_caf~, ~bogaert~ (Legendre only, ~n≥21~).
Preferred library entry: ~gauss_jacobi_rule(..., method=optional)~; omit method
or pass ~auto~ for ~select_method_auto~. ~imtqlx~ is *not* the absolute best for
large ~n~; ~sturm_caf~ parallelizes the GW eigenproblem by eigenvalue index,
~rec_caf~/~glr_caf~ by Newton node.

*** Coarray Fortran (~rec_caf~)
Full library CAF API notes: [[file:docs/CAF.org][docs/CAF.org]].

Independent half-interval Newton roots are owned round-robin across images
(~this_image~ / ~num_images~), then gathered with coarrays and ~sync all~.
With one image every index is owned by image 1 (same nodes/weights as ~rec~).

#+begin_src bash
# 1-image (always available with gfortran)
fpm run --flag "-fcoarray=single" gjp_quad -- 64 0.5 0.5 rec_caf

# Multi-image (OpenCoarrays + MPICH recommended for gfortran ≥14):
#   fpm build --flag "-fcoarray=lib" \
#     --link-flag "-L$OC/lib -lcaf_mpi -L$MPICH/lib -lmpifort -lmpi"
# Single-rule node partition (rec only):
#   cafrun -n 4 ./build/*/app/gjp_bench_caf single rec_caf 6144 0.5 0.5 7 3
# Multi-rule batch (all methods: rec, gw, algo665):
#   cafrun -n 4 ./build/*/app/gjp_bench_caf batch gw 256 64 0.5 0.0 5 2
#
# Reproducible toolchain / CI image (Nix dockerTools): see ~docker/caf/~.
#   cd docker/caf && nix develop
# Workflow: ~.github/workflows/caf_multiimage.yml~
#+end_src
*** Meson Support
A ~meson~ build backend is also present, which makes it easier to incorporate as subprojects of projects other than those supported by ~fpm~.

#+begin_src bash
meson setup bbdir
meson compile -C bbdir
./bbdir/gjp_quad <npoints> <alpha> <beta> <method>
#+end_src

*** External Fortran libaries
We support and encourage users to generate single file versions of the algorithms here to include in their code bases. This can be done with the ~scripts/add_headers.py~ script:
#+begin_src bash
# Strips comments by default
python scripts/export_single.py --modulename "gjp_algo665"
python scripts/export_single.py --modulename "gjp_gw" --keep-comments
#+end_src
These can be dropped into any code base or compiled as is into a shared library.
#+begin_src bash
gfortran dist/gjp_algo665_single.f90 --shared -fPIC -o libgjp_algo665.so
#+end_src
*** Interfaces
See [[file:interfaces/README.org][interfaces/README.org]] for full C/C++ and Python usage.

*** C/C++ interface
Preferred entry: ~gauss_jacobi_rule_c~ (by-value scalars, optional method, status
codes). Header: ~interfaces/CInterface/GaussJacobiQuadCInterp.h~. Methods:
~auto~, ~rec~, ~gw~, ~algo665~, ~algo665_dc~, ~sturm~, ~glr~, ~bogaert~.

#+begin_src bash
meson setup bbdir -Dfcoarray=single
meson compile -C bbdir
./bbdir/c_cli_gjpq 32 0 0 auto
./bbdir/c_cli_gjpq 40 0.5 0.5 glr
meson test -C bbdir c_rule
#+end_src

Decimals are not required for ~alpha~/~beta~ on the C CLI. Omit ~method~ for auto.

*** Python interface (ctypes → C ABI)
#+begin_src bash
export GJP_CINTERP=$(find bbdir -name libgjp_cinterp.so | head -1)
export PYTHONPATH=$PWD/interfaces/PyInterface:$PYTHONPATH
python -c "from gauss_jacobi_quad import gauss_jacobi; x,w=gauss_jacobi(32,0,0); print(x[:2], w[:2])"
python interfaces/PyInterface/gjquad_cli.py --npts 40 --alpha 0.5 --beta 0.5 --meth glr
pytest pytests/test_c_py_bindings.py
#+end_src

~method=None~/~auto~ uses the same policy as Fortran. Invalid ~bogaert~ raises
~GaussJacobiError~ (status code) instead of aborting the process.

** Notes
- The ~rec~ method fails for high values of ~beta~ so the ~gw~ method
should be used in such situations.
- ~algo665~ is an in-place variant of ~gw~ and is much faster when many points are needed
** Benchmarks
A very preliminary set can be run once all the interfaces have been compiled:
#+begin_src bash
# From $GITROOT
mv interfaces/PyInterface/gjquadpy*.so .
hyperfine --warmup 10 --export-markdown gjp_benchmarks.md \
    'bbdir/gjp_quad 5 2. 3. "gw"' \
    'bbdir/c_cli_gjpq 5 2 3 gw' \
    'PYTHONPATH=$(pwd) python interfaces/PyInterface/gjquad_cli.py --npts 5 --alpha 2 --beta 3' \
    'python scripts/scipy_gauss_jac.py --npts 5 --alpha 2 --beta 3' \
    'python scripts/sympy_gauss_jac.py --npts 5 --alpha 2 --beta 3 --n_dig 15'
#+end_src

Which gives:

** Development
*** Developing locally
A ~pre-commit~ job is setup on CI to enforce consistent styles, so it is best to
set it up locally as well (using [[https://pypa.github.io/pipx][pipx]] for isolation):

#+begin_src sh
# Run before commiting
pipx run pre-commit run --all-files
# Or install the git hook to enforce this
pipx run pre-commit install
#+end_src
*** Updating licenses
When the headers in the sources need to be updated modify ~add_headers.py~ and run:
#+begin_src sh
python scripts/add_headers.py --dirs src/ interfaces/ --ftypes "f90,f77" --cchar '!'
python scripts/add_headers.py --dirs interfaces --ftypes "c,h" --cchar '//'
python scripts/add_headers.py --dirs interfaces scripts --ftypes "py" --cchar '#'
#+end_src
Remember to do this before exporting the code into other projects (e.g. [[https://github.com/atomic-solvers/featom][featom]]).
